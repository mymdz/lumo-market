# Database schema

[Русская версия](../ru/database.md) · [Detailed guide](overview.md) · [README](../../README.md)

Every table and column written by the Lumo Market simulator.

- `shop` — marketplace business data (what CDC / lakehouse / BI read).
- `sim` — the simulator's internal state (needed for restarts, not meant for analytics).

Sources: base tables in `internal/adapters/postgres/schema.sql`, foreign keys and
indexes in `constraints.sql`, later columns in `internal/app/migrations.go`.

## Conventions

- **Time.** All `timestamptz` values are UTC. The only exception is
  `returns.received_at` (`timestamp` without a time zone, local warehouse time).
  No event column is ever in the future; only planning columns may be:
  `shipments.promised_at`, `purchase_orders.expected_at`,
  `campaigns.starts_at/ends_at`, `coupons.valid_from/valid_to`.
- **Money.** `numeric(12,2)`. Offer and purchase prices are in EUR; order,
  payment and refund amounts are in the order currency (`orders.currency`).
- **IDs.** Generated by the simulator (not `serial`), monotonically increasing within a table.
- **Foreign keys.** Created after the initial backfill as `NOT VALID`: enforced
  for new rows, not checked for history. `orders.cart_id` and
  `reviews.customer_id` have no FK on purpose (carts are deleted after 30 days,
  reviews survive GDPR erasure).
- **Migration columns** (marked ⓜ) appear at a simulated point in time; rows
  created before the migration contain `NULL`.
- **`updated_at`.** Changes on every UPDATE of the row, except during "bug
  windows" when `dirt_level > 0` (see the guide): then rows are updated without
  touching `updated_at`.
- Enumerations are stored as `text`; all values the simulator can write are listed below.

## Schema `shop`

### Reference data

#### `shop.currencies` — currencies

| Column | Type | Description |
|---|---|---|
| `code` | char(3) PK | ISO 4217: `EUR`, `PLN`, `CZK`, `SEK`, `DKK`, `MDL` |
| `name` | text | Currency name |
| `minor_units` | smallint | Number of decimal places (always 2) |

#### `shop.countries` — countries (markets)

| Column | Type | Description |
|---|---|---|
| `code` | char(2) PK | ISO 3166-1 alpha-2 (15 countries: DE, AT, NL, BE, FR, IT, ES, PT, IE, PL, CZ, SE, DK, FI, MD) |
| `name` | text | Country name |
| `currency` | char(3) | Market currency → `currencies.code` |
| `vat_rate` | numeric(5,2) | Standard VAT rate, % |
| `vat_reduced` | numeric(5,2) | Reduced VAT rate, % (books, food, kids' goods) |
| `timezone` | text | IANA zone (`Europe/Berlin`); the daily demand profile follows it |
| `is_eu` | boolean | EU member (`false` only for Moldova) |
| `launched_at` | timestamptz | Market launch; no orders from the country before it |

#### `shop.fx_rates` — exchange rates

One row per day and currency (except EUR).

| Column | Type | Description |
|---|---|---|
| `rate_date` | date PK | Rate date |
| `currency` | char(3) PK | Currency |
| `rate_per_eur` | numeric(18,6) | Currency units per 1 EUR |

#### `shop.warehouses` — Lumo fulfilment warehouses

| Column | Type | Description |
|---|---|---|
| `id` | smallint PK | 1 Leipzig, 2 Tilburg, 3 Poznań, 4 Zaragoza |
| `code` | text | Short warehouse code (`LEJ1`, `TLB1`, `POZ1`, `ZAZ1`) |
| `name` | text | Name |
| `country` | char(2) | Warehouse country |
| `city` | text | City |
| `timezone` | text | IANA zone of the warehouse (used for `returns.received_at` and the 14:00 cut-off) |
| `opened_at` | timestamptz | Opening; delivery times to the region drop afterwards |

#### `shop.categories` — category tree

Three levels: department (0) → group (1) → leaf category (2). Products are attached to leaves.

| Column | Type | Description |
|---|---|---|
| `id` | integer PK | Category ID |
| `parent_id` | integer | Parent → `categories.id`; `NULL` for departments |
| `name` | text | Name |
| `slug` | text | URL slug (`smartphones`) |
| `path` | text | Full path joined with ` > ` (`Electronics > Phones & Wearables > Smartphones`) |
| `level` | smallint | Depth: 0, 1, 2 |
| `is_active` | boolean | Category is active |
| `created_at` | timestamptz | Created |
| `updated_at` | timestamptz | Last change |

#### `shop.brands` — brands

| Column | Type | Description |
|---|---|---|
| `id` | integer PK | Brand ID |
| `name` | text | Name |
| `tier` | text | Price tier: `budget`, `mid`, `premium` |
| `country` | char(2) | Country of origin (may be outside the markets: CN, US, JP...); `NULL` if unknown |
| `is_private_label` | boolean | Lumo's own label |
| `created_at` | timestamptz | Brand added to the catalog |

### Marketplace and catalog

#### `shop.sellers` — sellers

| Column | Type | Description |
|---|---|---|
| `id` | integer PK | Seller ID; `1` is Lumo Retail (the marketplace itself) |
| `name` | text | Storefront name |
| `legal_name` | text | Legal entity |
| `country` | char(2) | Country of registration (including CN) |
| `seller_type` | text | `1p` — Lumo's own retail, `3p` — third-party seller |
| `status` | text | `onboarding` → `active` ⇄ `suspended` → `closed`. A suspended seller's offers become `paused` |
| `rating` | numeric(3,2) | Seller rating 1–5, recalculated from cancellations/delays; `NULL` until there is data |
| `joined_at` | timestamptz | Joined the marketplace |
| `updated_at` | timestamptz | Last change |
| `closed_at` | timestamptz | Left the marketplace (when `status = closed`) |

#### `shop.suppliers` — suppliers

| Column | Type | Description |
|---|---|---|
| `id` | integer PK | Supplier ID |
| `brand_id` | integer | Brand, if the supplier distributes a single brand; otherwise `NULL` |
| `name` | text | Name |
| `country` | char(2) | Country |
| `lead_time_days` | numeric(5,1) | Average lead time, days |
| `created_at` | timestamptz | Created |

#### `shop.products` — products

| Column | Type | Description |
|---|---|---|
| `id` | bigint PK | Product ID |
| `category_id` | integer | Leaf category → `categories.id` |
| `brand_id` | integer | Brand → `brands.id`; `NULL` for no-name products (partly "dirt") |
| `title` | text | Title (with dirt: double spaces) |
| `description` | text | Description; may be `NULL` or HTML |
| `status` | text | `active` → `discontinued` (end of life, clearance) → `deleted` |
| `weight_g` | integer | Weight, grams |
| `attributes` | jsonb | Product-level attributes (`{"tier": "budget"}` etc.) |
| `successor_id` | bigint | Next product generation (`Nova 12 Pro` → `Nova 13 Pro`) → `products.id` |
| `launched_at` | timestamptz | Market launch |
| `discontinued_at` | timestamptz | Discontinuation |
| `created_at` | timestamptz | Product created |
| `updated_at` | timestamptz | Last change |
| `eco_score` ⓜ | char(1) | Eco rating `A`–`E`. Migration `m003` (−310 days); 2 months later ~40% of older products are backfilled |

#### `shop.product_variants` — variants (SKUs)

Size / colour / storage of a particular product.

| Column | Type | Description |
|---|---|---|
| `id` | bigint PK | Variant ID |
| `product_id` | bigint | Product → `products.id` |
| `sku` | text | Internal SKU (`LM-LFLT-01`) |
| `ean` | char(13) | EAN-13 barcode; `NULL` if missing |
| `variant_name` | text | Human-readable name (`128 GB / Black`); `NULL` for products without variants |
| `attributes` | jsonb | Variant axes (`{"color_tech": "Black", "storage_phone": "128 GB"}`) |
| `status` | text | `active` |
| `created_at` | timestamptz | Created |
| `updated_at` | timestamptz | Last change |

#### `shop.offers` — seller offers

A variant can be sold by several sellers; orders reference an offer.

| Column | Type | Description |
|---|---|---|
| `id` | bigint PK | Offer ID |
| `variant_id` | bigint | Variant → `product_variants.id` |
| `seller_id` | integer | Seller → `sellers.id` |
| `price` | numeric(12,2) | Current price, EUR (converted at the daily rate for non-EUR markets) |
| `list_price` | numeric(12,2) | "Strike-through" price (RRP) |
| `currency` | char(3) | Always `EUR` |
| `fulfillment` | text | `platform` — stored in a Lumo warehouse (stock in `stock_levels`), `seller` — the seller ships it |
| `stock_qty` | integer | Seller's stock; only for `fulfillment = seller`, otherwise `NULL` |
| `handling_days` | smallint | Seller's handling time in days; only for `seller` |
| `status` | text | `active`, `paused` (seller suspended), `deleted` |
| `created_at` | timestamptz | Created |
| `updated_at` | timestamptz | Last change (price, status, stock) |

#### `shop.price_history` — offer price history

| Column | Type | Description |
|---|---|---|
| `id` | bigint PK | Change ID |
| `offer_id` | bigint | Offer → `offers.id` |
| `old_price` | numeric(12,2) | Price before, EUR |
| `new_price` | numeric(12,2) | Price after, EUR |
| `reason` | text | `repricing`, `competitor_match`, `cost_increase`, `campaign_start`, `campaign_end`, `clearance` (selling off a discontinued product), `successor_launch` (a new generation came out) |
| `changed_at` | timestamptz | Moment of the change |

### Warehouse and purchasing

#### `shop.stock_levels` — stock in Lumo warehouses

Only for offers with `fulfillment = platform`.

| Column | Type | Description |
|---|---|---|
| `warehouse_id` | smallint PK | Warehouse → `warehouses.id` |
| `offer_id` | bigint PK | Offer → `offers.id` |
| `qty_on_hand` | integer | Physical stock (can be negative when oversold) |
| `qty_reserved` | integer | Reserved for orders not yet shipped |
| `reorder_point` | integer | Reorder point: a purchase order is created below it |
| `updated_at` | timestamptz | Last change |

#### `shop.stock_movements` — stock movements

| `ref_id` | bigint | Source document ID |

#### `shop.purchase_orders` — purchase orders

#### `shop.purchase_order_items` — purchase order lines

#### `shop.orders` — orders

All amounts are in the order currency. `grand_total = items_subtotal − discount_total + shipping_fee`
(prices include VAT; with dirt there are rare 1-cent mismatches).

| Column | Type | Description |
|---|---|---|
| `id` | bigint PK | Order ID |
| `order_number` | text | Customer-facing number, `LM-<year>-<7 digits>` |
| `customer_id` | bigint | Customer → `customers.id`; `NULL` for a guest order |
| `guest_email` | text | Guest email (only when `customer_id IS NULL`) |
| `cart_id` | bigint | Source cart (no FK: carts get deleted) |
| `status` | text | see below |
| `currency` | char(3) | Order currency = market currency |
| `fx_rate` | numeric(18,6) | Rate on the order date: currency units per 1 EUR (1 for EUR) |
| `country` | char(2) | Delivery country / market |
| `items_subtotal` | numeric(12,2) | Sum of lines before discount, VAT included |
| `discount_total` | numeric(12,2) | Discount (coupon, campaign) |
| `shipping_fee` | numeric(12,2) | Shipping fee (0 when free) |
| `tax_total` | numeric(12,2) | VAT included in the total |
| `grand_total` | numeric(12,2) | Amount to pay |
| `coupon_id` | integer | Applied coupon → `coupons.id` |
| `shipping_address_id` | bigint | Shipping address → `addresses.id` |
| `billing_address_id` | bigint | Billing address |
| `channel` | text | `web_desktop`, `web_mobile`, `ios_app`, `android_app` |
| `shipping_method` | text | `standard`, `express`, `locker` (parcel locker) |
| `placed_at` | timestamptz | Placed |
| `paid_at` | timestamptz | Paid successfully (cash on delivery: at handover) |
| `cancelled_at` | timestamptz | Cancelled |
| `cancel_reason` | text | `customer_request`, `payment_failed`, `payment_timeout`, `cod_refused` (cash on delivery refused), `seller_cancelled` |
| `created_at` | timestamptz | Row created |
| `updated_at` | timestamptz | Last change |
| `utm_source` ⓜ | text | `google_organic`, `google_ads`, `instagram`, `tiktok`, `awin`, `referral`, `newsletter`. Migration `m002` (−470 days) |
| `utm_campaign` ⓜ | text | Campaign slug (`black_friday_week`, `brand_week:_klarvo`...). Migration `m002` |

`shipped` → `delivered` → `partially_returned` / `returned`; early statuses can
go to `cancelled`.

## Schema `sim` (internal)

The simulator's internal state. It changes in the same transaction as `shop`
data, which makes restarts safe. Not meant for analytics: the fields are encoded
parameters of the behaviour model.

#### `sim.meta` — engine state (single row, `id = 1`)

| Column | Type | Description |
|---|---|---|
| `id` | smallint PK | Always 1 |
| `phase` | text | `backfill` or `live` |
| `sim_time` | timestamptz | Current simulated time |
| `horizon` | timestamptz | First launch: the boundary between history and live; migration offsets are relative to it |
| `start_time` | timestamptz | Start of history (`horizon − history_days`) |
| `seed` | bigint | Random generator seed |
| `state` | jsonb | Serialized engine state (ID counters, traffic controller, calendar etc.) |
| `finalized` | boolean | Backfill finished, indexes and FKs created |
| `updated_at` | timestamptz | Last checkpoint (wall time) |

#### `sim.migrations` — applied `shop` schema migrations

| Column | Type | Description |
|---|---|---|
| `id` | text PK | Migration ID (`m001_shipments_co2`...) |
| `applied_at` | timestamptz | When it was actually applied (wall time) |
| `sim_time` | timestamptz | Simulated moment of application |

#### `sim.customer_traits` — hidden customer parameters
